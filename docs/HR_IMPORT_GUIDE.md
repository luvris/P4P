> มาเป็นตัวอย่างในเอกสารหรือ commit ลง Git — ใช้ค่าสมมติเท่านั้น

## ✅ อัปเดตเมื่อ: 2026-10-05 (เวอร์ชั่น 3.0)

หน้า **"นำเข้าข้อมูลบุคลากร"** เลิกใช้ไฟล์แบบเดิม (PID / HID / SER ฯลฯ) แล้ว
เปลี่ยนมาใช้ **ไฟล์เงินเดือนรูปแบบใหม่ (39 คอลัมน์)** ไฟล์เดียวกับที่ใช้นำเข้าเงินเดือนฝั่งการเงิน
โดยอ่านข้อมูลบุคลากรจากคอลัมน์ของไฟล์นั้นโดยตรง

> ไฟล์แบบเก่า (`HrXlsxParser`, `HrImportService`) ถูก **ลบออกจากระบบแล้ว**
> ถ้าอัปโหลดไฟล์ที่ไม่มีคอลัมน์ ลำดับที่ / ปี / เดือน ระบบจะตอบกลับ `422` ว่า
> "ไฟล์นี้ไม่ใช่ไฟล์เงินเดือนรูปแบบใหม่"

## 1. รูปแบบไฟล์ที่รองรับ

ไฟล์เดียวกันนี้ใช้ได้ทั้ง 2 ที่:

| หน้า | ปลายทาง API | ผลลัพธ์ |
| --- | --- | --- |
| นำเข้าข้อมูลบุคลากร (`/hr/import`) | `POST /api/hr/imports` | อัปเดตตาราง `employees` 1 แถวต่อคน |
| นำเข้าข้อมูลเงินเดือน (`/finance/import`) | `POST /api/finance/imports` | เก็บ `payrolls` ทุกงวดทุกแถว |

คอลัมน์ฝั่งบุคลากรที่ระบบใช้ (ทั้งหมดมาจากไฟล์เงินเดือนรูปแบบใหม่):

| คอลัมน์ในไฟล์ | ใช้ทำอะไร |
| --- | --- |
| `id card` | **กุญแจ** — ใช้ upsert ทะเบียนบุคลากร |
| `ปี` + `เดือน` | งวดของแต่ละแถว (ใช้เลือก "งวดล่าสุดต่อคน") |
| `คำนำหน้า`, `ชื่อ`, `นามสกุล` | ชื่อ-สกุล |
| `ประเภท` | → `employee_type_id` |
| `ตำแหน่ง` | → `position_id` (สร้างใหม่ให้อัตโนมัติถ้ายังไม่มี) |
| `ตำแหน่งเลขที่` | → `employees.position_number` |
| `เลขที่บัญชี` | → `employees.bank_account` |
| `เงินเดือน` | → `employees.latest_salary` + `latest_period_year/month` |

คอลัมน์รายรับ-รายจ่ายที่เหลือ (`รวมรายรับทางตรง`, `รวมรายรับทางอ้อม`,
`ยอดรวมรายรับทั้งหมด รายบุคคล` ฯลฯ) ไม่ถูกใช้ตอนนำเข้าบุคลากร — ดูรายละเอียดที่
[EXCEL_TO_DATABASE_MAPPING.md](./EXCEL_TO_DATABASE_MAPPING.md)

## 2. ไฟล์รวมหลายงวด → ระบบเลือกงวดล่าสุดให้เอง

ไฟล์เงินเดือนจริงของหน่วยงานมักรวมหลายงวดในไฟล์เดียว
(ตัวอย่างไฟล์จริง: 2,673 แถว = 8 งวด × ~349 คน) คนเดิมจึงปรากฏหลายแถว

ขั้นตอนของระบบ:

1. อ่านทุกแถวพร้อมงวดของแถวนั้น (`ปี` + `เดือน`)
2. คำนวณ **ปีงบประมาณ** — เดือน ต.ค.–ธ.ค. ใช้ปีงบ = ปี พ.ศ. + 1, ที่เหลือใช้ปี พ.ศ. เดิม
3. ยุบเหลือ **1 แถวต่อคน** โดยเอาแถวที่งวดใหญ่ที่สุด
   (เช่น คนที่มีถึง ธ.ค. 2569 จะได้ ธ.ค. 2569 ไม่ใช่ พ.ย. 2569 ที่อยู่ทีหลัง)
4. แถวที่ **ไม่มีเลขบัตรประชาชน** = ข้อมูลไม่ครบ → ข้าม พร้อมขึ้นคำเตือน
   "ข้ามแถวลำดับที่ N — ไม่พบเลขบัตรประชาชน"

ผลที่ได้จากไฟล์ตัวอย่างจริง: 2,673 แถว → **349 คน** (เพิ่มใหม่ 347 / อัปเดต 2)

## 3. ขั้นตอนการนำเข้า

1. เข้าเมนู **"นำเข้าข้อมูลบุคลากร"** (`/hr/import`)
2. เลือกประเภท = **นำเข้าข้อมูลบุคลากร**
3. อัปโหลดไฟล์ `.xlsx` (≤ 10 MB)
4. กด **"ดูตัวอย่างข้อมูล"** — ระบบแสดง 10 คนแรกของงวดล่าสุด พร้อมคอลัมน์
   *ลำดับที่ · งวดเดือน · คำนำหน้า · ชื่อ · นามสกุล · ประเภท · ตำแหน่ง · ตำแหน่งเลขที่ ·
   เลขบัตรประชาชน · เลขที่บัญชี · เงินเดือน · การดำเนินการ (เพิ่มใหม่/อัปเดต)*
   พร้อมสรุปจำนวน "เพิ่มใหม่ / อัปเดต" และคำเตือน (ถ้ามี)
5. กด **"ยืนยันนำเข้าข้อมูล"**
6. หน้าจอสรุปผล: ทั้งหมด / เพิ่มใหม่ / อัปเดต / ข้าม-ผิดพลาด

⏱️ ไฟล์จริงใช้เวลาประมาณ **10–20 วินาที** ต่อครั้ง (อ่านไฟล์ + เขียนฐานข้อมูล)
หน้าเว็บตั้ง timeout การอัปโหลดไว้ที่ 180 วินาที ถ้าเห็นข้อความ
"timeout of 10000ms exceeded" แปลว่าเป็นเบราว์เซอร์ที่ยังโหลดโค้ดเก่าอยู่ — รีเฟรชหน้า

## 4. การเขียนลงฐานข้อมูล

ทำทั้งหมดใน `DB::transaction` เดียว ถ้ามีแถวใดผิดพลาดจะ rollback ทั้งก้อนและ
บันทึก `imports.status = failed` พร้อมข้อความ error

| ตาราง | การเปลี่ยนแปลง |
| --- | --- |
| `employees` | เพิ่มใหม่/อัปเดตตาม `citizen_id` — คำนำหน้า, ชื่อ, นามสกุล, `employee_type_id`, `position_id`, `position_number`, `bank_account`, `latest_salary`, `latest_period_year`, `latest_period_month`, `updated_by` |
| `positions` | สร้างตำแหน่งใหม่อัตโนมัติถ้ายังไม่มี (จับคู่ด้วยชื่อแบบตรงตัว) |
| `imports` | `import_type = hr`, `inserted_rows`, `updated_rows`, `success_rows`, `status` |

หมายเหตุ: คอลัมน์ `ประเภท` และ `คำนำหน้า` จับคู่กับตารางอ้างอิงแบบ **ชื่อตรงตัว**
(ยุบช่องว่างซ้ำก่อนเทียบ) ถ้าไม่พบชื่อที่ตรงกันจะเว้นว่างไว้ ไม่ได้สร้างชื่อใหม่ให้เอง

## 5. ⚠️ ข้อควรระวัง

1. **เลขบัตรประชาชนคือกุญแจ** — แถวที่ไม่มีเลขบัตรจะถูกข้าม (พร้อมคำเตือน)
2. **งวดในไฟล์ถูกยุบเหลืองวดล่าสุด** — ถ้าคนหายจากไฟล์หลังงวดใดงวดหนึ่ง
   ระบบจะยึดงวดที่เขาปรากฏครั้งล่าสุด (ไม่ใช่งวดท้ายสุดของไฟล์) ซึ่งถูกต้องตามความหมาย
   "ข้อมูลล่าสุดที่มี" แต่ถ้าต้องการงวดเฉพาะเดือนให้เตรียมไฟล์ที่มีงวดนั้นเพียงงวดเดียว
3. **คอลัมน์เงินที่ว่างหรือเป็น `-`** ถือเป็น 0 (ทั้งฝั่งเงินเดือนและเงินสำรอง)
4. **สถานะ/ภารกิจไม่ได้อยู่ในไฟล์นี้** — ยังคงนำเข้าแยกผ่าน
   "นำเข้าข้อมูลการอยู่ภารกิจของบุคลากร" (ไฟล์ `PID | DUTY | PARTY | AGENCIES`)

## 6. นำเข้าข้อมูลการอยู่ภารกิจ (แยกอีกชุด)

| หัวข้อ | รายละเอียด |
| --- | --- |
| API | `POST /api/hr/duty-assignment-imports/preview`, `POST /api/hr/duty-assignment-imports` |
| รูปแบบไฟล์ | `PID` \| `DUTY` (ภารกิจ) \| `PARTY` (กลุ่มงาน) \| `AGENCIES` (งาน) |
| Key | เชื่อมด้วย `PID` = `employees.employee_id` |
| ผลลัพธ์ | อัปเดตเฉพาะ `duty_id`, `group_id`, `work_id` |

รองรับชื่อคอลัมน์ภาษาไทยด้วย (เช่น `รหัสบุคลากร`, `ภารกิจ`, `กลุ่มงาน`, `งาน`)
และตัดรหัส/คำนำหน้าที่ติดมากับค่า เช่น `59_กลุ่มงานการพยาบาลผู้ป่วยนอก`

## 7. แก้ปัญหา

| อาการ | สาเหตุ | แก้ไข |
| --- | --- | --- |
| `422 ไฟล์นี้ไม่ใช่ไฟล์เงินเดือนรูปแบบใหม่` | ขาดคอลัมน์ ลำดับที่ / ปี / เดือน หรือคอลัมน์รายรับหลัก | ตรวจสอบหัวตารางแถวแรกของไฟล์ |
| `422 ไม่พบข้อมูลบุคลากรในไฟล์` | ไม่มีแถวไหนมีเลขบัตรประชาชนเลย | ตรวจคอลัมน์ `id card` |
| ข้อมูลไม่ครบทุกคน | คนที่ไม่มีในไฟล์จะไม่ถูกแตะข้อมูล (ไม่ลบ, ไม่ล้าง) | ตรวจ `imports` ว่า `success_rows` ตรงกับจำนวนคนที่คาดหวัง |
| Network timeout | เบราว์เซอร์โหลด bundle เก่าที่ยังตั้ง timeout 10 วิ | รีเฟรชหน้าแบบ hard reload แล้วลองใหม่ |
